# Operational Gap Analysis

> **Disclaimer:** *Illustrative assumptions for portfolio case study — not real bank data.*

---

## 1. Gap Analysis Methodology

The Gap Analysis compares NovaBank's current operational state (**AS-IS**) against the desired future operating model (**TO-BE**), identifies specific operational and technological deficiencies (**Gaps**), quantifies the business impact, and prescribes targeted improvements categorized by **MoSCoW implementation priority**.

---

## 2. Structured Gap Analysis Matrix (12 Core Gaps)

| Gap ID | Process Dimension | AS-IS Current State | TO-BE Future State | Identified Operational Gap | Business Impact | Proposed BA Improvement | Priority (MoSCoW) |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :---: |
| **GAP-01** | **Document Quality & Intake** | Manual inspection of uploaded documents 24–48h post-submission. | Instant real-time pre-validation at the point of customer upload. | No client-side image DPI (≥300 DPI), file format, or completeness validation. | High document rework rate (35%); idle waiting latency (+7.3h). | Deploy automated document pre-validation engine with instant error feedback. | **Must Have** |
| **GAP-02** | **Document Requirements Clarity** | Static generic document list shown to all applicants regardless of profile. | Dynamic tailored checklist generated based on employment & loan type. | System does not adapt required document requests based on applicant segment. | Customers submit incomplete/irrelevant files; 18% held for info requests. | Implement profile-driven dynamic document checklist engine. | **Must Have** |
| **GAP-03** | **Data Integration & Re-Keying** | Operations staff manually type data across CRM, KYC, LOS, and Core Banking. | Unified API data synchronization across all internal platforms. | No RESTful API integration bus connecting disparate legacy databases. | 11.5% transcription error rate; 22% manual handoff delays (+4.0h). | Build enterprise API microservices data orchestrator layer. | **Must Have** |
| **GAP-04** | **Credit Assessment & Scoring** | Credit analysts manually pull bureau reports and calculate DTI on spreadsheets. | Direct bureau API ingestion with algorithmic DTI calculation engine. | Absence of automated credit bureau integration and calculation engine. | High credit assessment cycle time (4.5h); calculation inconsistencies. | Implement direct credit bureau API ingestion and real-time DTI scoring. | **Must Have** |
| **GAP-05** | **Underwriting & Decisioning** | 100% manual review of all loans in a single undifferentiated FIFO queue. | Automated Straight-Through Processing (STP) for Tier 1; exception queue for Tier 2. | Lack of rule-based automated decisioning and risk segmentation. | 9.5 hours of idle queue wait time; underwriter bandwidth congested. | Deploy automated credit decision engine with STP for low-risk applicants. | **Must Have** |
| **GAP-06** | **Customer Status Transparency** | Zero status tracking available; customers receive no mid-process updates. | Self-service 5-stage milestone tracker on web portal and mobile app. | No customer-facing tracking interface or real-time status synchronization. | High inquiry burden on branches (3.2 calls/loan; 32,000 calls/mo). | Deploy customer self-service milestone tracking portal. | **Must Have** |
| **GAP-07** | **Customer Notifications** | Manual email notifications dispatched in batches hours after status change. | Automated event-driven push notifications (SMS, Email, WhatsApp). | Absence of an automated omni-channel messaging notification service. | Delayed customer response time (average 26 hours to upload missing docs). | Implement automated event-driven notification trigger service. | **Must Have** |
| **GAP-08** | **Operational SLA Monitoring** | Reactive management; team leads discover breaches only after customer complaint. | Real-time SLA dashboard with automated alerts at 50% & 75% thresholds. | No real-time task timer monitoring or automated pre-breach alerts. | 14.0% SLA breach rate (1,400 loans/month missing 5-day SLA). | Deploy proactive SLA countdown engine with automated team lead alerts. | **Should Have** |
| **GAP-09** | **Agreement Signing** | Physical paper loan sanction letters printed, signed, and scanned at branches. | Instant mobile OTP-based cryptographic digital e-Signature. | No legal digital e-Signature capability integrated into origination flow. | Post-approval settlement delay of 24–48 hours; printing courier costs. | Integrate digital e-Signature gateway for instant contract execution. | **Must Have** |
| **GAP-10** | **Loan Disbursement Trigger** | Operations officers manually verify paper files and enter batch payment codes. | Automated API funds transfer release to Core Banking upon e-Sign verification. | Manual verification gate disconnected from Core Banking payment rails. | 24-hour disbursement latency post-approval; risk of payment keying errors. | Deploy automated Core Banking API disbursement trigger service. | **Must Have** |
| **GAP-11** | **KYC & Watchlist Verification** | Manual copy-pasting of national IDs into external government portals. | Automated real-time API verification against National ID & AML databases. | Manual compliance checks creating operational bottleneck. | High KYC cycle time (6.0 hours); compliance backlog. | Integrate automated National ID Registry & AML screening APIs. | **Must Have** |
| **GAP-12** | **Underwriter Decision Workbench** | Underwriters toggle across 5 open application windows to view files. | Unified single-screen workbench with pre-calculated ratios and risk highlights. | Fragmented user interface forcing disjointed cognitive workflow. | Slower manual underwriting reviews (1.5h touch time per file). | Deliver unified Underwriter Decision Workbench UI with consolidated view. | **Should Have** |
